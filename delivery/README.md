# 医疗信息化交付团（Healthcare IT Delivery Team）

端到端医疗信息化交付专家团：调研规划、方案架构、数据治理、实施运维一体协作，覆盖选型、云架构、维保与故障响应全流程。

## 类型

Team 型（多角色协作团队）

| medical-it-delivery-manager | 施立 | 实施计划、项目管理、维保体系、故障响应 |

## 功能

- **端到端交付方案**（默认 Workflow）：调研规划 → 架构+数据并行设计 → 实施运维保障 → 汇编报告
- **选型与架构专项**：模型能力、开发方式（自研/合作/采购）、供应商性价比、私有云/公有云/混合云、AI 部署架构
- **数据治理与测评专项**：数据标准、互联互通成熟度测评、电子病历分级、数据中台
- **实施运维专项**：实施路线图、切换与迁移、维保模式（传统维保 vs AI FDE）、故障响应体系
- **可信数据空间专项（Workflow D，v1.2 新增）**：选协作场景 → 数据权属/契约 → 身份+使用控制+隐私计算底座 → 数据分类分级与贡献计量 → 分期落地；契约未定不进架构
- **三医融合专项（Workflow E，v1.2 新增）**：DRG/DIP 政策与口径诊断 → 病案/结算清单/分组器一致性 → 病种成本 → 多部门实施与防变形监控；盈利率须 CMI 校正
- **信创可信专项（Workflow F，v1.2 新增）**：现状盘点 → 信创栈选型与数据库兼容层 → 数据分类分级 → 双轨并行切换+回退+等保密评节点；无回退不切换

方法论底座见仓库 [`knowledge/三大扩展方向-方法论底座.md`](../knowledge/三大扩展方向-方法论底座.md)。

## 协作与交付纪律（v1.1 新增）

角色能力之外，全部成员另有一套统一的协作契约，用于解决多角色协作里最常见的四类失效：

- **只与主理人通信**：成员之间不直连，跨成员对齐经主理人中转。并行分支各自改口径再合并，是返工成本最高的失败模式。
- **先落盘、再回传**：产出必须先写入文件，回传消息带绝对路径、行数、字节数。避免"写了但没交付"。
- **数字单一源**：金额、工期、指标门槛由主理人维护台账，变更须带废止声明。同一数字出现多个版本，是大型方案最高频的错误。
- **交付即冻结**：已交付内容不静默替换，改动由主理人裁定并广播。避免多版本并存与下游按旧值工作。

主理人侧另有：派发任务书六段模板（输入 / 约束 / 交付物 / 硬要求 / 下游接口 / 已裁决事项）、事实核验规则（涉及交付物内容必须读文件，不依据摘要或记忆判断）、汇编前的数字对账要求。

## 使用示例

- 我们是一家三甲医院，现有HIS系统老旧、数据分散，请团队做一套端到端的信息化升级交付方案。
- 请对比自研、合作开发与采购三种建设方式，并评估主流供应商的性价比。
- 医院要落地医疗大模型，请评估私有云与公有云部署方案及维保模式选择。
- 请团队做一套多中心科研可信数据空间的交付方案，要求数据不出各院、可用不可见。
- 请团队做一套面向DRG/DIP的交付方案，覆盖病案质量、成本核算和防止推诿重症的监控。
- 请团队做一套信创替换与等保密评交付方案，包含双轨并行和回退预案。

## 安装

将专家包目录放到本机专家 marketplace 的 `plugins/` 目录下（默认 `~/.workbuddy/plugins/marketplaces/my-experts/plugins/medical-it-delivery/`），然后运行注册命令使其在专家中心可见：

```bash
python3 <expert-manager-skill>/scripts/register_expert.py <expert-dir>
```

## 打包分享

```bash
python3 <expert-manager-skill>/scripts/package_expert.py <expert-dir> [output-dir]
```

打包产物为 zip，可直接分发给他人安装。
